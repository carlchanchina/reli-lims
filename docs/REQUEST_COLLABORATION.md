# 委托商业来源与门户协作

## 已实现：可选商业来源

Test Request 可独立手工创建，无报价/订单也可提交。可选关联 ERPNext Quotation 和 Sales Order；仅接受已提交商业单据，客户和公司必须与委托一致，并要求操作者有来源读取权限。若同时选择报价和订单，该订单至少一条明细必须引用选定报价。不复制报价/订单商品为实际 Sample 或检测项目，不据此自动收样或提交。复制委托时不复制商业来源。

商业单据不代表客户已确认检测要求；实验室确认仍由 Lab Manager 提交委托后创建 Project。一个报价/订单可能分批委托，因此单纯手工关联不设全局唯一约束；未来“从订单生成”须使用订单行/履约批次幂等键，不能假定一单一委托。

## 待实现：复用门户账号的协作权限

用户选择现有客户/商家门户账号。外部成员不能直接获得 Lab Manager/Lab Engineer 或任意 Test Request CRUD 权限。

目标步骤：实验室或客户创建草稿 → 指定客户组织及受邀第三方参与准备 → 提交客户确认版本 → 客户实名账号确认当前内容快照 → 实验室正式提交 → 创建 Project。第三方不能代替客户确认；客户确认不等同实验室正式提交，也不宣称具有法律电子签名效力。

每次业务内容修改使先前客户确认失效；确认记录绑定服务器计算的内容版本、实际用户和时间，禁止客户端直接写入。Lab Manager 的提交权限不因此授予外部账号。已提交主流程保持不可修改，变化应走后续受控变更流程。

外部门户接口必须从已有登录上下文解析用户/组织/商家，拒绝客户端自报组织；独立校验委托客户组织、实验室商家以及逐单受邀成员。白名单仅包括约定草稿字段，不能写 project、confirmed_by/on、company、业务阶段或执行/报告状态。原始文件与内部备注默认不共享；文件授权不能仅依赖委托列表权限。撤销邀请后须即时拒绝后续访问。

下一实施前置：核对现有门户代码和 Bridge 身份合同、客户组织到 ERP Customer 的映射及第三方邀请模型；相关代码不在本次 Reli LIMS 修改范围，尚未接通或授予外部账号权限。不使用公开链接作为客户确认凭据，不开放 Guest 编辑。此文中的协作步骤为待实现设计，不是已交付功能。
