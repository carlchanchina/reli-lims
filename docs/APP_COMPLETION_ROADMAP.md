## 已有主线

客户委托草稿 → 确认提交时创建 ERPNext Project → 实际收样生成 Sample → 创建 Test Program（多样品、多项目，每项目一个执行标准）→ Running → Completed → Reviewed → 报告审核、批准、签发。

## 当前片段：Project 关联总览

在原生 Project 的 Connections/关联区域追加“检测业务”，关联检测委托单、样品、试验方案、检测报告。沿用各文档的 project Link、原生列表筛选与权限，保留原生任务、销售、采购、费用等关联。不新建总览数据库、状态或自定义公开接口，不修改 ERPNext 核心。只有与当前 Project 关联且用户有权限的业务单据应可进入；未确认委托还没有 Project，不应冒充已立项。

验收：打开已有已确认委托的“项目”按钮；在 Project 关联区进入四类单据；检查 project 筛选；检查其他项目不会混入；无单据权限用户不能访问。此总览用于导航，不代表客户门户隔离已完成。

## 后续片段顺序

1. 供应商承接委托：复用既有商家身份及只读履约面板，补订单到委托草稿的受控映射。订单重放不得生成重复委托/Project；确认仍走现有提交事务。订单到达不伪造实收样品。
2. 客户查询：复用客户身份，只查本组织委托、送样要求、业务阶段和已签发报告；报告私有文件授权单独校验。先确认现有客户入口，避免另建登录体系。
3. Documents 来源连接：核对上游版本化已审核结构化导出合同，验证来源与实验室归属，补撤销/过期处理。保持 OCR/LLM/原文解析在 Documents。
4. Wiki/Mercur 投影：只消费已发布能力；取消发布可同步下架；委托、原始数据和私有报告不得成为公共知识页。

各片段按独立测试与可审查提交交付，未实施条目不能视为已上线。供应商不等同 ERP Company，客户不等同供应商；公开能力与私有履约权限分离。不扩展独立 React/Vue 管理后台。
