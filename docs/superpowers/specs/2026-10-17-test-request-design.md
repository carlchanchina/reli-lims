# 检测委托单与项目入口设计

日期：2026-10-17
状态：用户于 2026-10-17 确认本书面设计；实施计划待审阅。

## 已确认的目标

客户委托入口使用自研 Frappe DocType。委托单创建时即填写产品名称、型号、数量、体积／外形尺寸和照片；不是等实验室收样后才填写。一单支持多个样品，各检测项目指定适用样品、方法、标准和条件。确认委托单时只自动创建一个 ERPNext Project。实际收样后沿用委托资料生成 Sample，再生成 Test Program。Testing Center 同时提供委托单、项目和任务入口。

这是对既有入口的扩展：检测委托单 → ERPNext Project → Sample → Test Program → 实验项目 → 审核 → Test Report。已有项目直接登记样品、建立实验计划的路径继续可用。Project、Task、Customer、File 均复用 ERPNext/Frappe，不引入独立前端或复制财务模块。

## 数据结构

### Test Request（检测委托单）

原生 Desk 表单、可提交单据，编号 REQ-。主要字段：委托名称、客户（Customer，必填）、公司（Company，必填）、委托日期、交付日期（必填）、报告语言、报告份数（正整数，默认 1）、其他报告要求、备注、只读关联项目、只读确认人／时间。

子表分四组，避免 Frappe 不支持的子表嵌套：

| 子表 | 内容 |
| --- | --- |
| Test Request Sample | 稳定样品编号、客户样品编号、产品名称、型号、委托数量、体积／外形尺寸、备注 |
| Test Request Photo | 样品编号、照片（Attach Image）、说明；一行一张，支持多张 |
| Test Request Item | 稳定实验项编号、Test Method、唯一执行 Test Standard、检测条件 |
| Test Request Item Sample | 实验项编号、样品编号；一行一对，支持多对多 |

产品名称、正数量必填；型号、尺寸、照片可选，以支持不同种类样品。尺寸／体积先使用带单位文本，例如“200 × 100 × 50 mm”或“2 L”，不做体积自动计算。样品编号和实验项编号在委托单内唯一。每个实验项至少关联一个本单样品；照片必须引用本单样品。方法与标准继续独立选择，不绑定成永久 1:1。

照片通过 Frappe File 存储，使用私有附件并关联当前委托单。先保存草稿，再上传照片。服务端拒绝公共照片、其他单据的附件和无有效 File 记录的 URL；不直接接受任意外部图片地址。多照片映射在表单上按样品编号选择。

### 与后续记录的关联

Sample 增加可选委托单链接、来源委托样品行标识、体积／外形尺寸。实际样品保留接收日期、接收人、实际数量、外观状态等既有字段。来源行标识为唯一键，避免重复收样生成；手工登记且没有委托来源的样品不受影响。

Test Program 增加可选来源委托单链接；V1 每张委托单最多生成一份实验计划，其他手工实验计划继续可用。报告通过实验计划追溯委托单和报告要求，提供来源链接，不自动生成 PDF。

## 操作与状态

### 1. 填写并保存草稿

登记客户、计划交付、报告要求，以及全部委托样品、照片和检测项目。委托样品清单表达客户委托范围，不冒充已接收的 Sample。草稿可反复修改。

### 2. 确认委托单

由 Lab Manager 使用原生提交动作确认。校验完整范围、样品关联及私有照片后，在同一数据库事务中创建 Project：项目名称包含委托编号和名称、客户、公司、预计交付日期，状态 Open。回写项目链接、确认人和时间；不创建 Sample、Test Program、Task 或财务记录。

确认者必须具备正常的 Project 创建权限和客户／公司访问权限；缺失时明确报错并回滚，不以 ignore_permissions 绕过，不自动添加 ERPNext 角色。提交操作遵循 Frappe 文档并发校验，并锁定来源单据，重复调用或并发请求不能生成两个项目。创建项目或回写失败时整体回滚。

确认后的委托范围冻结。V1 不提供已确认委托的取消／改版流程；不授予取消权限，也不自动关闭或删除关联项目。项目后续状态和任务仍由 ERPNext 管理。确需修改已确认委托范围时使用后续修订功能，不能静默覆盖。

### 3. 实际收样

确认后显示“登记收样”按钮，选择尚未生成实际样品的委托样品行，填写接收日期、实际数量、接收人和状态备注。默认沿用产品名称、型号、尺寸和委托数量，可在收样对话框记录实际差异。差异需要填写说明。一次可接收多行，分次处理不同样品行；V1 每行一次生成一个 Sample，不实现同一行分批到货累计。

正常权限下事务性创建 Sample，关联委托项目和来源样品行。已生成的行再次操作返回已有记录，不重复创建；并发依靠来源行唯一键和来源单锁保护。照片沿用资料时为目标 Sample 建立受权限约束的私有 File 关联，保留委托原始附件，不把文件改为公共文件。实际收样照片仍可另附。

### 4. 生成实验计划

确认且所有委托样品行均已生成实际 Sample 后，提供“生成实验计划”。复制委托检测项目的方法、标准、条件及样品适用关系，项目和样品使用实际记录；生成 Draft，实验项 Pending，负责人、工程师和设备后续安排。关联委托单，交付日期填入计划结束日期作为初始值。

重复点击返回已有实验计划，不覆盖后续人工修改。任意一行样品未收齐时明确列出缺失行，不悄悄丢弃适用关系。委托报告要求通过来源链接在实验计划和报告中可查看。原有执行、审核、签发约束继续生效。

## 工作台与权限

Testing Center 增加检测委托单、项目（Project）、任务（Task）的快捷入口与导航链接。沿用 ERPNext 项目详情的任务列表及 Task.project 关联，不自动把每个 Test Program Item 再复制成一个 Task。

Lab Manager：创建／编辑草稿、确认、登记收样、生成计划；Lab Engineer：创建／编辑草稿、登记收样、生成计划；Lab Reviewer：只读。确认仅负责人；所有操作仍需目标 DocType 的原生创建／读取权限。Project 和 Task 入口不扩大角色权限，无权访问时沿用 Frappe 的权限行为。

## 验收与安全验证

1. 两行委托样品包含名称、型号、尺寸和多张私有照片；三个检测项目对应独立标准，分别选择适用样品。
2. 保存草稿不生成项目；确认恰好生成一个项目，带入客户、公司和交付日期。
3. 失败回滚、重复点击与并发确认不留下孤立／重复项目；客户端改写只读关联字段被服务端拒绝。
4. 收样沿用资料；实际数量有差异需说明；重复收样不重复建 Sample；未确认委托不能收样。
5. 收齐后生成一个 Draft 实验计划，项目／方法／标准／条件／适用样品正确，重复生成返回原记录。
6. 工程师不能确认；缺少 Project 创建权限的负责人不能绕过；跨单照片／样品关联被拒绝；匿名无法下载照片。
7. 原有两样品三实验到报告签发路径回归通过；既有无委托来源的记录无需补填。
8. 工作台可进入原生项目和任务，实验项目删除保护和报告冻结继续有效。

新增业务校验需要自动化测试；包括事务回滚、重复／并发生成和角色拒绝。数据库写入测试在隔离测试站运行，不能直接在 carl 运行全套测试。carl 部署前备份，使用明显 DEMO 数据做目标路径验收，保留真实业务记录。

## 本期边界

不包含报价／订单／付款、客户门户、电子签章、自动报告 PDF、自动建任务、同一委托行的分批收样、委托改版或自动 ERPNext 权限扩展。以上不影响本期入口与执行闭环。

## 设计自检

- 委托阶段已有完整样品资料与照片，实际收样无需重新录入。
- 确认只创建项目，符合已确认业务方向；收样和生成计划是后续明确动作。
- 子表不嵌套，实验项与样品多对多保持现有模型。
- 原生项目、任务、客户和附件得到复用；没有第二套 ERP 数据模型。
- 事务、并发、来源唯一性、私有文件和权限失败都有明确验收项。
