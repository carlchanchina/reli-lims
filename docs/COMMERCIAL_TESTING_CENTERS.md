# 商业接单中心、检测履约中心与首家实验室

## 两个 Desk 入口

商业接单中心面向销售，串起客户、询价、报价、客户确认与委托申请。检测履约中心沿用现有 Testing Center 工作区和路径，显示接收审核、收样、试验、报告及签发。交接使用同一张 Test Request，实验室确认后走既有 Project、Sample、Test Program 和 Test Report。继续支持客户直接送检。

第一版使用原生 Desk Workspace、Number Card、Shortcut 和列表。后续再按参考图加入阶段带、角色待办和最近记录。数字从授权查询得出，计数和跳转列表使用同一过滤条件。Inquiry 的来源、报价接受状态与 Bridge 对齐后再挂到接单中心。工作区角色只控制入口可见性，单据权限仍由现有规则控制。保留旧检测入口和快捷操作，待浏览器验收后再调整信息分组。

## 首家实验室数据与报价

1. 用已有 CNAS Workbench 的 out_v2 文件做 DEV 预检。118 个方法候选、207 个标准、660 条范围明细、另有 7 条待审记录。用稳定方法编码、标准编号及版本匹配主数据，用方法、标准版本、检测对象、条款、限制和来源定位比对范围。逐行解释 CSV 660 和种子库 650 的差异，保留来源和待审结果。原文件留在已有受控来源。
2. 在当前 main 上对照 PR #11，单独提取能力来源、范围导入、待确认/发布所需改动。复用已有 Laboratory Profile、Test Method、Test Standard。导入前输出创建、复用、冲突、待审清单。重复导入无重复记录，冲突停止处理并由管理员审核。标准生效及认可发布走原审批。
3. 在 ERPNext Item 增加对 Test Method 的明确关联。服务 Item 可销售且非库存，Item Price 由销售确认。方法页显示关联 Item。先验证三个样例：固定价、同方法不同规格价、超范围待复核。方法和标准允许多对多，服务规格不同可有不同 Item。设备沿用 Asset，按条件和可用性在履约阶段分配。
4. 复用 ERPNext Quotation。现有委托明细 item_code 是委托行标识；另存报价服务 Item 及报价行来源，保留已确认的方法、标准版本和条件。一个报价可有多个检测项，重试不得重复建委托。无法确认能力的项目进入人工复核，禁止作为已认可项目直接确认。
5. 在 192.168.10.204 现有独立 DEV 验收站点，验证销售和实验室各自的首页、三个样例、一次报价转委托、角色越权拒绝，以及重复导入和重复转单。验收通过后再批量启用可报价 Item。价格、认可状态和设备限制不能从样例猜填。

本 PR 交付两套 Desk 工作区的第一版入口；导入、报价关联、能力校验和浏览器验收属于下一批开发。无需新建 Frappe bench。
