## 1. 部署流程（串行、可回滚）

`tools/dev-site-deploy.sh` 是运行目录的唯一写入口：

| 约束 | 实现 |
| --- | --- |
| 禁止并行部署 | `flock` 排他锁，第二个部署排队或超时失败（实测锁占用时报错退出） |
| 禁止部署本地孤立提交 | `git fetch` 后校验提交存在于远端分支，否则拒绝 |
| 禁止带脏树切换 | 有未提交改动直接失败并列出文件 |
| 不切分支 | `checkout --detach`，避免并行会话互相改分支指针 |
| 失败回滚 | 迁移/构建/健康检查任一步失败自动回到部署前提交并复查 |
| 可审计 | `~/pilot/state/dev-site-deploy.{json,log}` 记录 ref、sha、前后版本、操作者、耗时 |

配套文档 `docs/DEV_SITE_DEPLOY.md` 与 `AGENTS.md` 的部署纪律：开发在自己的 worktree，
运行目录只接受脚本写入。开发站开启 `reload_python`，健康检查会等待 runner 重启
（首版脚本正是因此误判失败，已修复为 90 秒重试）。

## 4. 三中心导航与中文收口

- 侧边栏只剩四个入口且均为中文：`工作台首页`、`商业接单中心`、`检测履约中心`、`实验室能力中心`；

- 旧字典：`Detection Project` DocType 与自定义字段已不存在，仅剩 124 行历史表数据（无 UI 入口，
  保留备查）；新增测试防止代码里再出现旧字典引用。
